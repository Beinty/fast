# محرك الكتابة — أدوات القياس

نموذج مطابق لمحرك التصحيح الذي يعمل في `Dict.kt`، مع أبعاد الكيبورد الحقيقية
المقروءة من `KbLayout.kt` و`KeyboardView.kt`. الهدف واحد: ألا يُشحن أي تعديل على
المحرك قبل قياسه.

## كيف تشغّلها

```
cd tools
python3 suite.py v10p        # التقرير الكامل، أحد عشر صنفا من الغلط
python3 suite.py shipped     # نفس الحالات على إعدادات 9.0، للمقارنة
python3 persist.py v10p      # نفس الغلط مئة مرة، وبينها خمس إعادات تشغيل
python3 tune.py three        # يبحث عن الأوزان بالقياس، لا بالتخمين
python3 kb.py                # أبعاد الكيبورد: عرض الزر، المسافة بين السطور، المدى
```

## الملفات

| الملف | ماذا يفعل |
|---|---|
| `kb.py` | هندسة الكيبورد وحساب الأزرار المجاورة، كما في `KeyboardView.neighbours()` |
| `lex.py` | يقرأ `dict_*.bin/.rnk` و`keep_ar.txt` ومجموعة `IRAQI` من `Dict.kt` نفسه، وقاعدة شكل اللهجة |
| `eng.py` | `Dict.correctNear` كاملا، وكل وزن وكل مرحلة قابلة للإطفاء كي تُقاس وحدها |
| `suite.py` | يبني الحالات من القاموس الحقيقي ويقيس كل صنف منفردا |
| `persist.py` | يمشي على طريق `HucKeyboard.findFix` كله مع مخزن على القرص |
| `tune.py` | هبوط إحداثي على الأوزان، بخليط الأغلاط كما تحدث فعلا بالإبهام |
| `ranks.py` | يبني ملف الرتب على منحنى — جُرّب وخسر، والسبب مكتوب في `Dict.kt` |
| `cfgs.py` | إعدادات مسمّاة، كي يُعاد أي قياس بالحرف |
| `safe.txt` · `names.txt` | كلمات يكتبها وما بالقاموس: هنا يُقاس الضرر، وهو أهم من الدقة |
| `drop_ar.txt` · `drop_en.txt` | ما حُذف من القاموسين: مدخلات هي أصلا أغلاط مطبعية |
| `freq_ar.txt` · `freq_en.txt` | قوائم التكرار التي بُنيت منها الرتب |

## قاعدتان خرجتا من القياس

**الضرر قبل الدقة.** مئتان وسبع وسبعون كلمة يكتبها كل يوم وما موجودة بالقاموس —
`safe.txt` و`names.txt`. أي تعديل يرفع الدقة ويكسر واحدة منها تعديل خاسر.

**لا يُقاس إلا على نفس الحالات.** `suite.py` يبني الحالات بمدى ثابت (`GEN_RH`)
مهما تغيّر إعداد المحرك. أول مرة قِستُ بمدى متغيّر فتغيّرت الحالات مع الإعداد،
وكانت الأرقام تقارن شيئين مختلفين.
